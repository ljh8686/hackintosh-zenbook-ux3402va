## 三、根因详解：为什么卡、为什么调不了分辨率

### 现在的显示链路（有问题）

```
Intel Iris Xe (8086:A7A0)
    ↓
IONDRVFramebuffer（通用兜底驱动，不是真正的显卡驱动）
    ├── 不读 EDID（显示器 vendor-id = "unkn" 0x756e6b6e）
    ├── 只暴露 1 个显示模式：2560×1600 @ 1x，无刷新率
    ├── 显存只有 15MB
    └── 所有 UI 靠 CPU 软件渲染 → WindowServer 卡爆
```

实测证据：

```
VRAM: 15 MB
Kernel Extension Info: No Kext Loaded
显示器 vendor-id = 756e6b6e ("unkn")  ← EDID 完全没读到
IOFBConfig 里只有 1 个模式 ID=100（2560x1600）
CoreGraphics 枚举可用模式：只有 1 个
displayplacer 也无法切到 1280x800 HiDPI（报错）
```

### 为什么 WhateverXe 没起作用

`WhateverXe.kext 0.8.5` **已经加载**（`org.b00t0x.WhateverXe` 在跑），但它只是个 Lilu 插件，必须挂到 `com.apple.driver.AppleIntelTGLGraphics` 这个真正的驱动上才能工作。而**macOS Tahoe 26 把这个驱动删了**，所以 WhateverXe 加载了也接管不了 GPU。

> 修复必须装 `WhateverXe Graphics 0.4.5` 包，把 TGL 图形栈（`AppleIntelTGLGraphics.kext` 等）装回系统。安装包我已经下载并校验好，放在 E 盘了。

### 为什么改 OpenCore 启动分辨率能立刻改善

`IONDRVFramebuffer` 只继承 OpenCore 启动时的 GOP 模式。现在 OpenCore 设的是 `Resolution=Max`，选了面板原生 2560×1600 → macOS 唯一模式就是它。

**如果把 OpenCore 改成 `1280x800`，macOS 唯一模式就变成 1280×800：**
- 字体会变成约 2 倍大（解决「字体太小」）
- 渲染面积降到 1/4（卡顿再降一大截）
- 代价：画面精细度下降（但这是目前无显卡驱动下唯一能立刻改善日常体验的办法）

我把三档分辨率配置都生成好了，你可以按喜好选。

### 优先级 3：修蓝牙（止住 430 次/30 分钟崩溃风暴）

**现状：** 蓝牙硬件已识别，`IntelBluetoothFirmware 2.5.0` 已加载，但固件没传进芯片。日志显示 `Still cannot find USB Bluetooth Controller after 15 seconds`，于是 `bluetoothd` 每 15 秒崩溃重启一次，无限循环，白烧 CPU 和电池。

**临时止血（今晚就能做，防耗电）：** 打开「系统设置 → 蓝牙」手动关闭蓝牙开关。

**根治（EFI 层）：** 需要换 BlueToolFixup 版本或检查 IntelBluetoothFirmware 的固件变体。这个要改 EFI + 重启验证，我建议和显卡一起做。需要我做的话告诉我，我会把新 kext 放进 E 盘并配好 config。

### 优先级 4：修触控板（中等难度）

**现状：** `VoodooI2C`/`VoodooGPIO`/`VoodooI2CHID` 全部加载成功，但 `VoodooI2CDeviceNub`（设备 `ASUE120C`）状态是 `!registered !matched`，所以触控板没有事件。

**根因：** DSDT 里 `ASUE120C` 附近虽然有 `SBFB`/`SBFG`（I2C 总线描述），但中断配置不对。设备用的是 APIC 中断（`IOInterruptSpecifiers`），VoodooI2C 需要正确的 SSDT 引导才能绑定。

**修复：** 需要新增一个 SSDT 来配置 I2C 中断方式，属于中等难度 ACPI 工作，改错可能影响启动。我可以做，但建议在你有空、能随时重启验证的时候一起处理。

### 优先级 5：睡眠/发热

**现状：** `sleep=0`（永不睡眠）+ `displaysleep=0`（永不关屏）+ 显示驱动 `.Display_boot` 阻止系统睡眠。笔记本这样会持续发热、耗电。

**建议（确认睡眠不会睡死后启用）：**
```bash
sudo pmset -a sleep 20 displaysleep 10
```

> 黑苹果睡眠有睡死的风险，建议先小步测试。不改也不算错，只是更费电。

## 亮度：为什么不能调

亮度需要两样东西**同时**存在：

1. ACPI 的 `PNLF` 设备 —— ✅ 你有（`SSDT-PNLF.aml`）
2. **真正的显卡驱动**提供的背光 PWM 通道 —— ❌ 没有（现在是 `IONDRVFramebuffer` 兜底驱动）

实测：`DisplayServicesCanChangeBrightness() = False`，系统直接告诉你「这个显示器不能改变亮度」。

**所以：亮度也是 GPU 驱动缺失的连带问题。装上 WhateverXe Graphics 后，PNLF + 显卡驱动一起到位，亮度滑杆和 Fn 亮度键就能用了。**

## 键盘「不好用」

需区分是哪种「不好用」：

- **打字/按键本身不灵** → VoodooPS2 已加载，`VoodooPS2Keyboard` 在跑，一般是正常的。如果是某些键位不对，那是键位映射问题。
- **Fn 功能键（亮度/音量/风扇键）不响应** → 这是没装 MHelper 的典型表现。装好 MHelper 后，Fn 键由 MHelper 接管（媒体、屏幕亮度、键盘亮度、触控板、睡眠、Fn+F5 性能模式、Fn+F4 键盘灯效果）。
- **屏幕亮度 Fn 键** → 仍受亮度通道限制，要等 GPU 驱动。

> MHelper 文档说：如果同时装了 AsusSMC，要关掉它让 MHelper 接管 Fn 键（`sudo Extras/asussmc.sh off`）。**你这台机器 EFI 里没有 AsusSMC**，所以不用管，MHelper 直接接管。

# 【11 月 26 日 10:30 重大更新】找到显卡不工作的真正原因

## 一、发现了我自己造成的关键错误

**症状：** 装完 WhateverXe Graphics 后重启，TGL 驱动（`AppleIntelTGLGraphics` / `Framebuffer`）**确实加载了**，但显卡仍显示 `15 MB / No Kext Loaded`，`IOAccelerator` = 0，IONDRVFramebuffer 仍占着 GPU。

**根因：** 我昨天为了"优化"把 boot-args 里的 **`-disablegfxfirmware` 删掉了**，但 WhateverXe 官方 README 明确要求这是 **必需参数**：

> Required boot arguments: `-allow3d -disablegfxfirmware`

`-disablegfxfirmware` 阻止 macOS 给 iGPU 加载 GuC/HuC 固件，因为 WhateverXe 走的是"N97 无 GuC"路径。没有它 → 固件冲突 → `N97NativePreflight = No` → `N97NativeStartAllowed = No` → TGL 驱动加载但不接管 GPU。

实测证据（IORegistry 里 WhateverXe 的状态）：
```
N97Admission              = Yes    ← 认得设备 0xa7a08086
N97NativePreflight        = No     ← 预检失败
N97NativeStartAllowed     = No     ← 原生启动被拒绝（正是缺少 -disablegfxfirmware）
N97PhysicalIdentity       = 0xffffffffa7a08086  ← 正确识别本机 GPU
```

**已修复：** boot-args 恢复为
```
-v debug=0x100 keepsyms=1 -allow3d -disablegfxfirmware -igfxdvmt -vi2c-force-polling ctrsmt=full -ibtcompatbeta revpatch=sbvmm -wexdbg -alcdbg
```
已同步到 E 盘和内置 ESP（两处 config 逐字节一致，SHA256 `73cd3ef...`）。

> ⚠️ **这个修复需要重启才生效。** 重启后 `-disablegfxfirmware` 起作用，TGL 驱动才能接管 GPU，卡顿/分辨率/刷新率/字体/亮度会一起改善。

1. IONDRV 只认 GOP 给的那一个模式
2. GOP 只支持 2560x1600 和几个低分辨率，没有 16:10 的中间档（如 1920x1200/1680x1050）

**Q: 处理器只有 3 GHz？**

**Q: 显示器为什么是 42 英寸？**

## 第13节　核显内屏加速·WhateverXe 实验记录（2026-11-26 20:0x）

### 背景
官方 WhateverXe 0.8.5 在本机（RPL-H i9-13900H / Iris Xe 0xA7A0 rev04 / 内屏 2560x1600 非DSC eDP）
始终卡在原生启动门禁：N97GTStep=unknown / N97NativeStartAllowed=No / N97NativeReservedGGTT=No /
WEXDisplay13BootReady=No → VRAM 15MB、IONDRVFramebuffer 兜底、纯软件合成。对应上游 issue #212（open）。

### 三次实验（均需重启，已逐一验证）
1. 官方 0.8.5 + `-wex-edp-keep`（官方 README 对内屏黑屏的标准做法）
   → 能正常进系统，但门禁无变化（15MB，No）。
2. 换 vikenzo196 的 fork **0.8.3-gb3u.3**（release 明确面向 Raptor Lake-H DSC eDP 面板，
   测试机 Galaxy Book3 Ultra / i9-13900H / 0xA7A0 / macOS26.7.3 25G342，与本机同平台）
   → kext 成功加载（org.b00t0x.WhateverXe 0.8.3），但 `WEXEDPDSCAdmitted=No`，门禁无变化（15MB）。
3. fork + `-wex-edp-dsc -wex-edp-60`（强制开 DSC 通道 + 锁 60Hz）
   → **`WEXEDPDSCAdmitted` 变为 Yes（DSC 准入通过！）**，但更深一层的原生启动门禁仍全部为 No：
     N97NativeStartAllowed=No / N97NativePreflight=No / N97NativeReservedGGTT=No /
     N97DisplayStep=unknown / N97GTStep=unknown / WEXDisplay13BootReady=No；VRAM 仍 15MB。
     N97NativeBootSource=<01 000000 / ffffffff / 00000000 / 03000000 / 00000000>，[3]=3=NotSingleHDMI
     （linearPlan 因 bootDDI=0xFFFFFFFF 判 NotSingleHDMI），与官方同款。

### 技术结论
- 失败点已定位到 **reserved GGTT / native preflight**（`N97NativeReservedGGTT=No`），
  这是固件 GGTT 预留几何与 WEX 预期不匹配导致的，属内核门禁，不是简单开关能过。
- 当前 framebuffer-stolenmem=0x03C00000(60MB)，`IOFBMemorySize=16384000`(15.6MB)；
  官方 README 要求 BIOS DVMT=96MB（60MB 需 -igfxdvmt+framebuffer-stolenmem）——本机是 60MB 档。
- **公开可得的构建（官方0.8.5、vikenzo DSC fork、此前 jkbuha XPS fork）在本机这块 2560x1600 非DSC 内屏上，
  均无法通过原生启动门禁 → 内屏无法加速。** 已知能加速的情形是：①仅有外接 DisplayPort 的机型（issue #115，满血 Metal2）；
  ②DSC OLED 内屏（vikenzo 的 Galaxy Book3 Ultra）。本机属于"非DSC 普通内屏"，正好落在裂缝里。

## 2026-11-28 三硬件攻坚（触控板 / 内置麦克风 / 内置扬声器）— 方案已备，待真机验证

**内置麦克风（Intel SST 数字麦）**：证实内置麦是 Intel 智音(SST)数字麦（Windows 设备 `VEN_8086&DEV_AE20&SUBSYS_104316A3`），不在 ALC294 声卡上，AppleALC 任何布局都救不了。改用 `labrouss/IntelSSTDMIC` 1.0.3（ADL cAVS2.5），本机 HDA `8086:51ca` 需 `-sstdmicforce`。已装入内置 ESP、Kernel Add 顺序 Lilu→AppleALC→SimpleHDA→IntelSSTDMIC、boot-args 加 `-sstdmiclayout=auto -sstdmicfw=adl -sstdmicforce -sstdmicdbg`。待冷启动录音验证。
