# 显卡加速修复 · 操作手册

> 生成时间：2026-11-25 23:55（Asia/Shanghai）
> 机器：ASUS Zenbook UX3402VA（i9-13900H / Iris Xe `8086:A7A0` / 2560×1600）
> 系统：macOS 26.7.3（25G342）

---

## 一句话根因

WhateverXe 0.8.5 **已正确加载**，但它是 Lilu 插件，必须挂到 `com.apple.driver.AppleIntelTGLGraphics` 上才能工作。**macOS Tahoe 26 已删除这个 kext**，没有宿主 → 补丁无处可打 → 显卡 `No Kext Loaded`、显存只有 15MB、WindowServer 占 131% CPU → 界面卡顿。

修复思路：用 WhateverXe Graphics 0.4.5 把 TGL 图形栈**装回系统**，让 WhateverXe 有宿主可挂载。

### config.plist 改了什么（只有这 2 处）

```diff
- csr-active-config = 03 00 00 00   (0x3)
+ csr-active-config = 03 08 00 00   (0x803)   ← WhateverXe Graphics 官方要求

- boot-args = ... -disablegfxfirmware -igfxdvmt ...
+ boot-args = ... -igfxdvmt ... -wexdbg
   （去掉 -disablegfxfirmware，它会阻止 iGPU 固件加载；
     加 -wexdbg 便于开机看到 WhateverXe 是否接管 GPU）
```

其余 3409 行配置**完全未改动**（已逐项 diff 验证）。

## 你要执行的步骤

### 第 1 步：让新 config 生效

E 盘的 `EFI\OC\config.plist` 已经改好。但现在开机用的是**内置 ESP**（`disk0s1`，卷标 `MYASUS`）里的那份，两者不会自动同步。

**二选一：**

**方案 A（推荐，最稳）—— 从 E 盘启动**
1. 重启，开机看到 OpenCore 菜单时按 **F12**（或 Esc）
2. 在 BIOS 启动菜单里选 **1401** 这块 U 盘
3. 从 E 盘的 OpenCore 进入 macOS

**方案 B —— 改内置 ESP**
在 macOS 终端执行：
```bash
sudo diskutil mount disk0s1
# 通常挂到 /Volumes/EFI
cp /Volumes/EFI/OC/config.plist "/Volumes/1401/DSH修复资料/EFI-sandbox-20261125-231701/config-EFI-OC-before-$(date +%Y%m%d-%H%M%S).plist"
cp /Volumes/1401/EFI/OC/config.plist /Volumes/EFI/OC/config.plist
sync
```

### 第 2 步：重启后确认 WhateverXe 加载成功

进系统后打开「终端」：

```bash
# 1. 确认 WhateverXe 在跑
kmutil showloaded | grep -i whateverxe

# 2. 确认 csr 已变成 0x803
nvram -p | grep csr-active-config
# 期望看到 %03%08%00%00

# 3. 关键：确认显卡已接管（这是装包的前提）
system_profiler SPDisplaysDataType | grep -A2 -i "kernel extension"
```

> ⚠️ **只有第 3 条显示有驱动时，才能继续第 3 步。**
> 如果仍显示 `No Kext Loaded`，**不要装包**——装了会启动 panic。此时直接执行第 5 步回滚。

### 第 3 步：安装 WhateverXe Graphics（需要管理员密码）

```bash
sudo installer -pkg "/Volumes/1401/DSH修复资料/whateverxe-graphics/WhateverXe-Graphics-0.4.5.pkg" -target /
```

或者直接双击 pkg 用图形安装器。

安装器会自动：
- 写入 `AppleIntelTGLGraphics.kext`、`...Framebuffer.kext`、`...Compat.kext` 到 `/Library/Extensions`
- 写入 MTL / VA / GL Driver bundle 到 `/Library/GPUBundles`
- 重建 AuxKC（`/Library/KernelCollections/AuxiliaryKernelExtensions.kc`）
- 关闭 `AllowOnePassMetalScaling` 特性标志

### 第 4 步：重启并验证

```bash
# 显存应该是 GB 级别，不再是 15MB
system_profiler SPDisplaysDataType

# 应该能看到 Metal 支持信息
system_profiler SPDisplaysDataType | grep -i metal

# WindowServer 占用应该大幅下降
ps aux | grep -i windowserver | grep -v grep
```

预期：`VRAM` 不再是 15MB，`Metal` 有输出，界面不再卡顿。

### 第 5 步：回滚（出问题时）

**轻度回滚（只撤销 config）**：
```bash
sudo sh /Volumes/1401/DSH修复资料/RESTORE-EFI.sh
```

**完整回滚（含卸载 Graphics 包）**：
```bash
sudo rm -rf /Library/Extensions/AppleIntelTGLGraphics.kext
sudo rm -rf /Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext
sudo rm -rf /Library/Extensions/AppleIntelTGLCompat.kext
sudo rm -rf "/Library/GPUBundles/AppleIntelTGLGraphicsMTLDriver.bundle"
sudo rm -rf "/Library/GPUBundles/AppleIntelTGLGraphicsVADriver.bundle"
sudo rm -rf "/Library/GPUBundles/AppleIntelTGLGraphicsGLDriver.bundle"
sudo rm -rf "/Library/GPUBundles/XeCompilerAdapter.bundle"
sudo kmutil create -n aux -x -z -V release -r /Library/Extensions --allow-missing-kdk \
  -B /System/Library/KernelCollections/BootKernelExtensions.kc \
  -S /System/Library/KernelCollections/SystemKernelExtensions.kc \
  -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc --no-authentication
```
然后再跑 `sudo sh /Volumes/1401/DSH修复资料/RESTORE-EFI.sh`。

**如果完全开不了机**：从 E 盘启动（E 盘本身是可启动 OpenCore 盘），进 Recovery 或直接跑还原脚本。

---

## 风险提示（务必看）

1. **AuxKC 建好但 WhateverXe 加载失败 → 启动 panic**。所以第 2 步的验证绝对不能跳过。
2. **本机 `1043:16A3` 的 CS35L41 功放不在 CirrusAudioFixup 支持列表**，内建扬声器大概率还是不响，与本次显卡修复无关。
3. **FairPlay / DRM 内容（Netflix、Apple TV+）在 WhateverXe 下无法播放**，这是该方案的已知限制，不是故障。
4. **`-wexdbg` 会让开机 -v 画面输出大量调试信息**，验证成功后可以从 boot-args 里去掉。
