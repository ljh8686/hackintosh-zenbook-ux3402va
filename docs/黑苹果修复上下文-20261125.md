## 4. 网络 / Wi-Fi 现状

### 4.1 当前 EFI 的 Wi-Fi 方案

- 当前启用 `AirportItlwm.kext 2.4.0`，禁用 `itlwm.kext`。
- 这个 `AirportItlwm` 是 `laobamac/itlwm` 的 Tahoe alpha，AX211 `8086:51F1` 有理论支持；但它不是 Apple 原厂驱动，Tahoe 下可能遇到 vtable / OCLP root patch / SIP 兼容问题。
- 进 macOS 后先看：
  ```bash
  system_profiler SPAirPortDataType
  kextstat | grep -i airport
  log show --last 5m --predicate 'process == "kernel"' | grep -i airport
  ```
- 如果 Wi-Fi 菜单没有接口，先把 `itlwm` + HeliPort 作为“非原生”备选；`itlwm` 不是 macOS 原生 Wi-Fi，需要在系统里运行 HeliPort。
- 另一条备选是 `ForbiddenItlwm`：
  - 文件已放在 `E:\DSH修复资料\ForbiddenItlwm-0.6.0-beta.4-Tahoe.zip`
  - 配套 `BTLEAdvFixup-0.9.4-Tahoe.zip` 同目录
  - 它支持 AX211 + Tahoe，不依赖 OCLP Wi-Fi root patch，但属实验性 AI 辅助内核代码；之前我们在另一版 EFI 里加它时出现过直接卡引导，**不要和 AirportItlwm 同时加载**，必须保留可回滚 EFI。
- USB 无线网卡：Realtek RTL8188ETV（`0BDA:0179`）已确认在 Windows 下工作；macOS 需要 `chris1111/macOS-RTL-WIFI` + RTLWiFiBar，属于 Ethernet 风格的非原生方案，不能用于安装器联网，但可作装好系统后的临时网络。

### 4.2 不要重复的坑

- 不要在安装器里指望 Intel AX211 直接出现原生 Wi-Fi；`itlwm` 没有 HeliPort 就不会有菜单。
- 不要把 `AirportItlwm` 和 `ForbiddenItlwm`、`itlwm` 同时启用。
- 不要为了 Wi-Fi 去改 `csr-active-config` 到 `0x803` 以外再乱动；先确认当前 SIP 状态和 WhateverXe 需求。

## 5. 音频 / 触控板 / 蓝牙

### 音频

- 本机是 ALC294 + CS35L41 智能功放，子系统 `1043:16A3`。
- 当前 EFI 用 `AppleALC` + `SimpleHDA` 路线（1401 构建的音频选项）。
- 内建扬声器需要 CS35L41 的 board profile/固件；`CirrusAudioFixup` 支持列表里只有同系列 **UM3402Y `1043:1683`**，本机 `1043:16A3` 不在列表，所以内建扬声器很可能需要自己匹配 profile，不能保证响。
- 3.5mm 耳机通常由 AppleALC 负责，比扬声器更有希望。
- 进系统后先查：
  ```bash
  system_profiler SPAudioDataType
  ioreg -l | grep -i -E 'CS35L41|ALC294|AppleALC'
  ```
- 不要同时装 VoodooHDA 和 AppleALC。

### 触控板

- `ASUE120C` 是 I2C HID；当前 VoodooI2C 全套已启用。
- 如果触控板不动，先查：
  ```bash
  ioreg -l | grep -i -E 'VoodooI2C|VoodooGPIO|ASUE120C'
  ```
- 可能需要针对 GPI0 的 SSDT/中断补丁；不要直接把 VoodooI2C 全删掉。之前最小化测试时曾关闭过 VoodooI2C，证明它不是当前引导卡死的主因。

### 蓝牙

- Intel `8087:0033`，EFI 里已有 `IntelBluetoothFirmware + IntelBTPatcher + BlueToolFixup`。
- 进系统后：
  ```bash
  system_profiler SPBluetoothDataType
  ```
- 如果蓝牙反复重启，先检查 USB 端口映射和 `BlueToolFixup` 版本，不要同时启用冲突的 Bluetooth kext。

## 7. 在 macOS 里用 DSH 的操作建议

1. 先找到 E 盘：
   ```bash
   ls /Volumes
   # 应看到 1401（或类似卷标）
   cd /Volumes/1401
   ```
2. 让 DSH 以 `/Volumes/1401` 为工作目录，先读本文件：
   ```bash
   cat "/Volumes/1401/DSH修复资料/黑苹果修复上下文-20261125.md"
   ```
3. 挂载内置 ESP（修改内置 OpenCore 才需要）：
   ```bash
   diskutil list
   sudo diskutil mount disk0s1
   # 通常会挂到 /Volumes/EFI
   ```
4. 修改前备份：
   ```bash
   cp /Volumes/EFI/OC/config.plist "/Volumes/1401/DSH修复资料/config-backup-$(date +%Y%m%d-%H%M%S).plist"
   ```
5. 每次只改一个变量（一个 kext、一个 boot-arg 或一个 csr 设置），重启验证后再改下一个。
6. 如果改坏了，优先从 E 盘启动（E 盘本身是可启动的 OpenCore 盘），再用备份恢复；不要直接拿内置 ESP 做实验。

## 8. 建议的排查顺序

1. **先确认 macOS 能稳定进桌面**，记录当前 `system_profiler SPDisplaysDataType`、`SPAirPortDataType`、`SPAudioDataType`、`SPBluetoothDataType` 的输出。
2. **显卡/内屏**：确认 WhateverXe 加载状态、WhateverXe Graphics 是否安装、`csr-active-config` 与 `AMFIAnchor` 是否符合官方要求。不要先动 `AAPL,ig-platform-id` 等 DeviceProperties，除非有对应机型的明确参考。
3. **Wi-Fi**：先测当前 `AirportItlwm 2.4.0`；不行再试 `itlwm + HeliPort`；最后才考虑 `ForbiddenItlwm`（并且单独启用、保留回滚）。
4. **音频**：先测耳机口；内建扬声器再查 CS35L41 profile / CirrusAudioFixup。
5. **触控板/键盘**：VoodooI2C + VoodooPS2 当前已启用，先查 ioreg，不要整组禁用。
6. **蓝牙**：最后处理，避免和 Wi-Fi/USB 映射互相干扰。
7. **电池/亮度/睡眠**：在显卡和音频稳定后再做，避免把启动问题混在一起。

## 9. 不要做的事

- 不要格式化 E 盘或删除 E 盘个人文件。
- 不要格式化 Disk 0 分区 4（macOS）。
- 不要删除内置 ESP 的 `EFI\Microsoft`。
- 不要把 `AirportItlwm`、`ForbiddenItlwm`、`itlwm` 同时启用。
- 不要直接套用 `1401macdiy.qd.je` 的预构建 EFI / `UTBMap.kext` / `CCToolBox`；该站点是第三方 SEO 教程站，不是 NullMoth 官方，EFI 来源不可验证。
- 不要在没备份 EFI 的情况下改 `csr-active-config` 或安装 WhateverXe Graphics。
- 不要把 `WhateverXe` 与 `WhateverGreen` 同时启用。
