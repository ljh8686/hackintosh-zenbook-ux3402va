## 一、内置网卡：已经在正常工作了 ✅

**结论：不需要修，你的 Intel AX211 已经在跑，而且连的就是它。**

实测证据：

```
系统信息 → Wi-Fi → 接口:
  en0:
    Card Type: Wi-Fi (0x8086, 0x94)          ← Intel 厂商 ID
    Firmware: itlwm: 2.4.0_7204c69 fw: 68.01d30b0c.0
    Status: Connected                         ← 已连接
    PHY Mode: 802.11n, Channel 1 (2GHz)
    Transmit Rate: 144

网络服务顺序:
  (1) Wi-Fi  Device: en0                      ← 唯一网络服务
  Hardware MAC: 8c:e9:ee:f2:1c:5a             ← 8c:e9:ee = Intel OUI

当前联网接口:
  en0 → inet 10.206.163.237                   ← 正在承载流量
  默认路由 → 10.206.163.213 (en0)
```

**关键点：**

- `en0` 的 `Card Type 0x8086` 是 Intel 的 PCI 厂商 ID，**这是内置 AX211 在跑**
- 你之前以为的「USB 网卡」——那个 `802.11n NIC`（Realtek RTL8188，`0BDA:0179`）**现在根本没插在机器上**
- 系统里**没有任何 RTL8188 驱动加载**（`kmutil showloaded | grep rtl` 为空）
- 所以你现在上网靠的就是内置网卡，一根 USB 都不用插

### 那为什么你会觉得「一直插着无线网卡」？

可能是这几种情况之一：

1. **之前**在装系统阶段确实插过 USB 网卡（因为安装器里 Intel 网卡不工作），系统装好后你已经拔掉了，但印象还停在那个时候
2. 你以为 `AirportItlwm` 不工作——它**工作得很好**，`Status: Connected` 就是证据
3. 界面右上角 Wi-Fi 图标显示正常，但你把某个 USB 设备（比如 `ETU905A88-E`，一个 USB 转接头）误认为网卡

**如果你现在确实还插着 USB 网卡**，拔掉它，网络不会断——因为流量走的是 `en0`。

### 如果想进一步优化（可选，不急）

当前连的是 2.4GHz、802.11n、20MHz、144Mbps，没跑到 AX211 的能力上限：

```bash
# 看是否能用 5GHz / 802.11ac
# 在「系统设置 → 网络 → Wi-Fi → 详细信息」里确认首选频段
# 或者在路由器上确认 5GHz SSID 已开启
```

`AirportItlwm 2.4.0` 支持 802.11ac，但当前 AP 给的是 802.11n。这是**路由器配置问题，不是驱动问题**。

## 二、声卡：根因是 Apple 删了 AppleHDA

### 根因（这是 Tahoe 的已知变化，不是配置错误）

我全量扫描了系统里全部 702 个 kext，**确认 `AppleHDA.kext` 完全不存在**：

```
S/L/E kext 总数: 702
HDA 相关只剩 1 个: AppleGFXHDA.kext (com.apple.driver.AppleGFXHDA)
                 ↑ 这是「显卡 HDMI/DP 数字音频」，不是板载声卡
```

网上的资料也一致（[Dortania 官方 Tahoe 说明](https://github.com/dortania/OpenCore-Install-Guide/blob/master/extras/tahoe.md)、[AppleALC README](https://github.com/acidanthera/AppleALC)）：

> macOS 26 Tahoe beta 2 起，Apple 完全移除了 `AppleHDA.kext`。因为 Tahoe 还支持的 Intel Mac 全都带 T2 芯片（音频由 T2 处理），Apple 认为不再需要 AppleHDA。**黑苹果没有 T2**，所以 AppleALC 依赖的底层驱动直接没了。

这解释了你现在的状态：

```
system_profiler SPAudioDataType → Devices: (空)
kmutil showloaded | grep AppleALC → (无)
EFI 里也没有 AppleALC.kext  ← 之前根本没配过音频
```

**你的 EFI 里从头到尾就没有 AppleALC**，交接文档里说的「当前 EFI 用 AppleALC + SimpleHDA 路线」与事实不符。

### 修复方案：AppleALC + SimpleHDA 双驱动

- **AppleALC 1.9.8**：处理 ALC294 codec 的初始化（pin config、layout）
- **SimpleHDA 1.0.2**：通过 OpenCore 注入恢复原版 AppleHDA（**不需要改系统卷、不需要重建内核集合**）

两者配合才能出声：AppleALC 认 codec，SimpleHDA 提供 AppleHDA 这层驱动。

### 已经做好的改动

**1. 拷入两个 kext** → `/Volumes/1401/EFI/OC/Kexts/`

```
AppleALC.kext   1.9.8   as.vit9696.AppleALC        3.6MB
SimpleHDA.kext  1.0.2   cn.laobamac.SimpleHDA       5.1MB
```

**2. 加入 `Kernel → Add`，顺序严格为 Lilu → AppleALC → SimpleHDA**

```
[0] Lilu.kext
[1] AppleALC.kext        ← 新增
[2] SimpleHDA.kext       ← 新增 (MinKernel 25.0.0)
[3] AMFIPass.kext
...
```

**3. 注入 `layout-id` 到音频控制器**

```xml
PciRoot(0x0)/Pci(0x1F,0x3)
  layout-id = 15000000   (0x15 = 21)
```

ALC294 可用的 layout ID 有 `11 12 13 15 21 22 24 28 44 66 99`，这台机器是 ASUS 笔记本，先试 **21**（Andres ZeroCross 的通用 ALC294 布局）。

**4. boot-args 加 `-alcdbg`**，方便开机看 AppleALC 是否工作

### 完整 diff（对比改动前备份）

```
LISTLEN /Kernel/Add: 32 -> 34
   + AppleALC.kext, SimpleHDA.kext
ADDED   /DeviceProperties/Add/PciRoot(0x0)/Pci(0x1F,0x3)
   = {layout-id: 15 00 00 00}
```

其余配置一字未动。

## 三、你要做的

### 重启即可生效

E 盘的 `EFI/OC/config.plist` 已经是新版。重启后：

1. 从 **E 盘**（1401）启动，让新配置生效
2. 进系统后验证：

```bash
# 1. 看驱动是否加载
kmutil showloaded | grep -iE "applealc|simplehda"
# 期望看到 as.vit9696.AppleALC 和 cn.laobamac.SimpleHDA

# 2. 看声卡是否出现
system_profiler SPAudioDataType
# 期望有 "Devices:" 下面列出内建输出/输入

# 3. 看音频控制器
ioreg -l | grep -i "layout-id"
```

### 如果没声音

**按顺序试不同 layout ID**（只改这一个数字，每次改完重启）：

```
21 → 13 → 15 → 44 → 66 → 11
```

修改方法：编辑 `/Volumes/1401/EFI/OC/config.plist`，找到：

```xml
<key>PciRoot(0x0)/Pci(0x1F,0x3)</key>
<dict>
    <key>layout-id</key>
    <data>FQAAAA==</data>   <!-- FQAAAA== = 21 -->
</dict>
```

对应的 base64：
| Layout ID | base64 |
|---|---|
| 11 | CwAAAA== |
| 13 | DQAAAA== |
| 15 | DwAAAA== |
| 21 | FQAAAA== |
| 22 | FgAAAA== |
| 44 | LAAAAA== |
| 66 | QgAAAA== |

**如果还是没声音**，装可选的 HAL 插件（需要 sudo）：

```bash
sudo installer -pkg "/Volumes/1401/DSH修复资料/audio/shda/SimpleHDA-Tahoe-v1.0.2-RELEASE/SimpleHDA-HAL-1.0.2.pkg" -target /
```

### 关于内建扬声器（CS35L41）

这台机器是 **ALC294 + CS35L41 智能功放**（子系统 `1043:16A3`）。Linux 内核补丁记录显示：

> The UX3402VA (1043:16a3) BIOS leaves pin 0x19 unconfigured, so the headset mic does not work. Use ALC294_FIXUP_ASUS_SPI_HEADSET_MIC.

**预期结果：**
- ✅ **3.5mm 耳机** 大概率能正常出声
- ⚠️ **内建扬声器**（CS35L41）成功率较低——AppleALC 没有这台机器对应的 CS35L41 profile

先验证耳机口，如果耳机能响，说明整条链路通了，剩下只是扬声器功放的单独问题。

## 五、还有一件事：显卡

你现在显卡还是 `No Kext Loaded`、15MB 显存，因为 **WhateverXe Graphics 包还没装**。

这次重启后如果要修显卡，流程是：

```bash
# 1. 先确认 WhateverXe 加载且显卡被接管
system_profiler SPDisplaysDataType | grep -i "kernel extension"

# 2. 只有确认有驱动，才能装 Graphics 包
sudo installer -pkg "/Volumes/1401/DSH修复资料/whateverxe-graphics/WhateverXe-Graphics-0.4.5.pkg" -target /
```

⚠️ 顺序不能颠倒，否则会启动 panic。详见 [操作手册-显卡加速修复.md](操作手册-显卡加速修复.md)。
